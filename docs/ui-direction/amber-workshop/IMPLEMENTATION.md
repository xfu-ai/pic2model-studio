# Amber Workshop 前端实施方案

## 目标

以本目录 9 张 `1600 × 900` 方向稿为逐页视觉基准，只优化审美、信息层级和布局，不改变任何业务能力、状态流转、接口调用或安全边界。

## 强制原则

1. 现有组件中的按钮、输入、筛选、选择、导入、导出、生成、错误处理、加载状态和结果入口全部保留。
2. AI Agent 默认常驻右侧，桌面宽屏保持约 `380–400px`，不得被页面参数面板替换。
3. 六个工作区页签完全平级，不使用编号、连线、箭头、完成度、锁定或步骤语义。
4. 视觉实现使用现有 React、CSS Grid/Flex、CSS Variables 和 Phosphor Icons，不引入新 UI 框架。
5. 不修改 provider、Job、资产、权限、文件能力 ID、Tauri 命令和 API 契约。

## 实施顺序

### 阶段 1：全局视觉基础

- 将全局 Token 切换为暖石墨与黄铜色体系。
- 重构顶栏层级：品牌与服务状态、项目与当前资产信息分层。
- 左侧主导航统一图标、文字、选中面和间距。
- 六页签改为等宽平级导航，仅当前页签使用黄铜色下划线。
- Agent、底部任务栏、弹窗、输入、按钮和状态色统一。

### 阶段 2：六个工作区页面

- 图片主页：左侧资产信息、中间沉浸画布、画布边缘工具。
- 参考 Prompt：紧凑双参考轨道 + 分段 Prompt 编辑器。
- 图像生成：参数轨道 + 大图结果舞台 + 候选胶片。
- 目标提取：来源/设置 + 精调画布 + 裁切/结果。
- 三视图：来源工具 + 三框裁切画布 + 输出质量。
- 3D 模型：沉浸式视口 + 紧凑顶部工具条。

### 阶段 3：全局功能页面

- 资产：稳定的混合资产网格，按图片、Prompt、JSON、GLB 调整密度。
- 任务：有最大宽度的任务工作区，统一状态、筛选、任务内容和操作对齐。
- 导出：居中工具面板，常用项目包与 Legacy 兼容功能分层。

## 功能保留检查

每个页面实施前后按现有组件和测试逐项核对：

- 所有可见按钮仍存在，原事件处理函数和 disabled 条件不变。
- 所有输入、选择、筛选、缩放、裁切、拖拽和键盘交互保持原行为。
- 加载、空、成功、失败、中断、等待审批和只读状态保持可见。
- 生成结果、候选选择、设置当前资产、进入下一工作区和返回任务中心入口保持可用。
- Agent 的 History、New、会话、工具输出、审批、图片结果、输入发送和参数固定保持可用。

## 验证门禁

### 组件与构建

1. 按页面运行最小相关 Vitest。
2. 运行 `pnpm --dir desktop/frontend build`。
3. 任一失败必须修复并重新运行同一验证。

### 真实桌面验证

1. 按 `docs/controlled-validation.md` 清理仅属于本仓库的旧 Tauri、sidecar、Vite 进程。
2. 使用受控 provider 启动并保留 WebView2 Debug Host。
3. 通过 CDP 的真实 DOM 事件逐页切换导航并验证主要交互。
4. 至少覆盖图片导入/预览、Prompt 页面、生成结果/候选选择、目标提取、三视图、3D、资产、任务和导出入口。
5. 保留脱敏后的 `dom.html`、`runtime.json`、`workspace.json`、`webview.png` 和交互断言。
6. 将运行截图与对应方向稿同视口比较，修复 P0/P1/P2 视觉差异。

只有组件测试、构建和受控 WebView2 真实验证全部通过，任务才可标记完成。
