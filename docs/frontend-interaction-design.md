## 2. 产品定位

本产品不是把现有桌面程序的多个页签直接搬到浏览器，而是构建一个由 AI Agent 驱动的本地 3D 资产创作工作台。

用户可以在右侧通过自然语言表达目标，Agent 根据当前项目、当前选中资产、历史对话和画布状态理解意图。一次用户输入可以触发多轮 Tool Calling，连续完成分析、生成、拆分、验证和模型转换等复杂任务。左侧工作区同步展示每一步的输入、执行状态和结果，并允许用户在需要判断或精细操作时接管。

产品的核心关系是：

```text
用户意图
  → Agent 结合持久上下文理解任务
  → Agent Loop 连续调用一个或多个 Tool
  → 左侧工作区实时呈现过程与结果
  → 在审批、选择、画布操作或异常处暂停
  → 用户完成操作或回复后继续原 Agent Run
```

应用关闭后，项目、会话、Agent Run、画布模式和后台任务均可恢复。再次打开时，用户不需要重新描述上下文。

## 3. 目标用户

### 3.1 主要用户

#### 游戏美术与技术美术

- 有明确的资产目标，关注轮廓、视角一致性、拓扑规模、材质和导出格式。
- 希望快速从概念图得到可预览的 3D 结果。
- 能判断图像或模型质量，但不希望手动串联多个外部 API。

#### 独立开发者与小型游戏团队

- 需要低成本完成角色、道具、场景物件的初步资产生产。
- 更关注完整流程是否易用，不一定熟悉 Prompt 或模型参数。
- 需要 GLB、FBX 等能进入现有引擎或 DCC 工具的格式。

#### 概念设计与原型人员

- 主要工作发生在图片阶段，偶尔需要快速验证 3D 化效果。
- 偏好通过对话修改意图，并在多个生成版本之间选择。
- 需要清楚了解当前结果是由哪张输入图和哪些操作产生的。

### 3.2 用户能力假设

- 用户理解“原图、参考图、三视图、模型”等基本概念。
- 不要求用户理解 API 请求、Tool Calling 或 Agent 状态机。
- 高级用户可以展开参数面板，普通用户使用推荐参数即可。
- 用户可能随时在对话和直接画布操作之间切换。

## 4. 设计目标与原则

### 4.1 设计目标

1. 用户能通过一句自然语言启动简单或复杂任务。
2. Agent 的执行过程始终可见、可暂停、可恢复、可追溯。
3. 图片、选区、三视图和 3D 模型始终是界面视觉中心。
4. 用户在需要精确判断时能无缝接管，不必放弃当前 Agent Run。
5. 应用重开后恢复到离开前的项目、会话和工作状态。
6. 低频高级参数不干扰主流程，但在需要时可快速访问。

### 4.2 设计原则

#### 以资产为中心

界面围绕“当前正在处理的资产”组织，而不是围绕 API、模型厂商或技术模块组织。用户始终能回答：

- 我正在看哪个资产？
- 它来自哪里？
- Agent 正在对它做什么？
- 下一步需要我做什么？

#### 对话驱动，但不隐藏操作

Agent 是主要入口，但不是唯一入口。所有关键 Tool 都应在左侧工作区有可见的操作入口，Agent 调用与用户手动调用共用同一种结果表达。

#### 多步执行透明

一次复杂请求可以连续调用多个 Tool，但界面必须逐步显示当前阶段、输入、参数、输出和暂停原因。禁止使用长时间无反馈的“正在思考”覆盖整个过程。

#### 人机协作优先

需要审美判断、版本选择或精细框选时，应主动暂停，让用户在左侧画布完成操作。用户确认后继续同一个 Agent Run，而不是开启一条割裂的新任务。

#### 状态可恢复

任何重要交互都应落到可恢复状态：当前会话、当前选中资产、画布缩放、选区、工具执行进度、待审批动作和未完成任务。

#### 渐进披露

默认只显示对当前任务有意义的工具和参数。高级参数、完整执行日志和资产来源通过抽屉或详情面板按需展开。

#### 本地感知

明确告诉用户文件存储在本机、外部 API 会上传哪些素材、输出保存到哪里。界面不使用“云端同步”等不存在的概念。

## 5. 信息架构

### 5.1 一级结构

```text
应用
├─ 项目选择与最近项目
├─ 主工作台
│  ├─ 项目导航
│  ├─ 资产工作区
│  ├─ 上下文参数区
│  └─ Agent 对话区
├─ 任务中心
├─ 本地文件与导出
└─ 设置
   ├─ Agent 模型
   ├─ 图像模型
   ├─ 3D 服务
   ├─ 本地路径
   ├─ 审批策略
   └─ 外观与快捷键
```

### 5.2 主工作台导航

左侧一级导航不按旧版六个固定页签组织，而按用户心智划分：

| 导航项 | 内容 | 使用频率 |
|---|---|---|
| 工作区 | 当前图片、选区、三视图或模型的主要操作画布 | 最高 |
| 资产 | 当前项目的图片、视图、模型和导出物 | 高 |
| 版本 | 当前资产的生成分支、来源与对比 | 中 |
| 任务 | Agent Run、后台任务、失败和等待项 | 中 |
| 导出 | GLB、FBX、图片及项目包 | 中 |

设置作为全局入口放在窗口底部，不占用主导航的高频位置。

### 5.3 工作区模式

工作区根据当前资产和 Agent 意图自动切换，也允许用户手动切换：

1. 空白引导模式
2. 图片预览模式
3. 图片对比模式
4. 矩形框选模式
5. 多结果选择模式
6. 三视图编辑模式
7. 3D 模型预览模式
8. 任务等待模式
9. 错误诊断模式

工作区切换不改变当前对话。Agent Run 可以要求打开某个模式并等待用户操作。

## 6. 全局布局

### 6.1 桌面端标准布局

目标设计尺寸以 1440 × 900 为基准，兼容 1280 × 720，推荐在 1920 × 1080 下使用。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶部栏：项目 / 当前资产 / 保存 / 任务 / API 状态 / 设置             52 px │
├──────┬───────────────────────────────────────┬───────────────────────────────┤
│      │ 工作区标题与上下文工具栏       44 px │ Agent 标题、会话与 Run 状态   │
│ 64px ├───────────────────────────────────────┤                               │
│ 导航 │                                       │                               │
│      │            主操作画布                 │        对话消息区             │
│      │                                       │                               │
│      │                                       │                               │
│      ├───────────────────────────────────────┤                               │
│      │ 参数 / 版本 / 任务详情抽屉            │                               │
│      │                               0–280px │                               │
│      │                                       ├───────────────────────────────┤
│      │                                       │ 对话输入区              96px │
├──────┴───────────────────────────────────────┴───────────────────────────────┤
│ 全局任务状态栏：后台任务、进度、输出路径、警告                         28 px │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 6.2 尺寸建议

| 区域 | 建议尺寸 | 行为 |
|---|---:|---|
| 顶部栏 | 高 52 px | 固定 |
| 左侧主导航 | 宽 64 px | 固定，可显示 Tooltip |
| 右侧 Agent 面板 | 宽 400 px | 可在 360–520 px 之间拖动 |
| 工作区 | 剩余宽度 | 不小于 680 px |
| 工作区工具栏 | 高 44 px | 根据模式变化 |
| 参数抽屉 | 高 240–280 px | 默认收起，按需展开 |
| 底部任务状态栏 | 高 28 px | 可点击展开任务中心 |
| 对话输入区 | 最小高 96 px | 随输入内容增长，最大 220 px |

在 1440 px 宽度下，推荐 Agent 面板占约 30%，工作区占约 70%。在超宽屏上限制 Agent 面板最大宽度，避免聊天内容行宽过长。

### 6.3 面板调整

- Agent 面板可以折叠为 48 px 状态条，折叠后保留当前 Run 状态、未读数量和恢复按钮。
- 参数抽屉可以固定展开，也可以仅在 Agent 请求用户确认参数时自动展开。
- 用户调整过的面板尺寸需按项目保存并在重开后恢复。
- 双击分隔条恢复默认宽度。

## 7. 顶部栏与全局反馈

### 7.1 顶部栏内容

从左到右：

1. 应用标志与产品名。
2. 当前项目名称，点击切换最近项目。
3. 保存状态：已保存、保存中、未保存、恢复失败。
4. 当前资产面包屑，例如“角色原图 / 拆分 v2 / 三视图 v1”。
5. 后台任务汇总。
6. 外部服务状态。
7. 导出快捷入口。
8. 设置。

### 7.2 本地与外部服务提示

顶部服务状态只展示综合状态：

- 本地服务正常
- 部分外部 API 未配置
- 外部服务不可达
- 有任务等待恢复

点击后打开详情，不在顶部显示 API Key 或技术错误堆栈。

对于会上传素材到外部服务的操作，在首次使用和审批卡片中明确展示：

> 将上传：当前角色图、正面/侧面/背面裁图
> 目标服务：已配置的 3D 生成服务
> 原始项目文件仍保存在本机

## 8. 左侧工作区详细设计

### 8.1 空白引导模式

适用于新项目或项目没有资产时。

中央只提供三个主要入口：

- 拖入或选择图片
- 拖入已有 GLB
- 在右侧告诉 Agent 想做什么

示例引导语：

> 拖入角色或道具图片，或者告诉 Agent：“分析这张图是否适合做 3D 模型。”

空白态不展示所有参数和工具，避免首次使用时产生压力。

### 8.2 图片预览模式

#### 主功能

- 适应画布、100% 显示、放大、缩小。
- 鼠标滚轮缩放，以光标位置为缩放中心。
- 按住空格或中键平移。
- 查看透明通道背景。
- 查看原始尺寸、格式、文件大小和版本来源。
- 切换原图、当前版本和父级版本。
- 将当前图片设为 Agent 默认目标。

#### 上下文工具栏

- 选择
- 框选拆分
- 对比
- 生成变体
- 生成三视图
- 更多

高成本或外部 API 操作点击后进入确认流程，不直接静默执行。

#### 当前资产标识

画布左上角显示紧凑信息：

```text
角色拆分 v2
2048 × 2048 · PNG · 透明背景
来源：生成图 v3 → 自动分割 → 手动修正
```

### 8.3 图片对比模式

支持：

- 左右并排。
- 拖杆叠加对比。
- 闪烁切换。
- 同步缩放和平移。
- 显示两个版本的 Prompt、模型和关键参数差异。

用户可选择：

- 设为当前版本。
- 回到父版本。
- 让 Agent 解释差异。
- 用左侧内容和右侧风格继续生成。

### 8.4 矩形框选模式

这是元素拆分和局部导出的主要交互模式。首版只支持矩形选框，不提供套索、画笔或擦除。

#### 工具

| 工具 | 用途 |
|---|---|
| 矩形框 | 快速框选规则区域 |
| AI 建议框 | 由视觉能力建议目标区域 |
| 清除 | 清除当前选择 |
| 撤销/重做 | 恢复最近操作 |

#### 交互要求

- 所有选区以原始图片像素坐标保存，与画布缩放无关。
- 选区边界使用高对比色，并配合半透明遮罩，不只依赖颜色区分。
- 矩形框支持拖动、八方向缩放和数值输入。
- 可同时保留多个命名选区，例如“角色主体”“武器”“底座”。
- Agent 可以创建建议选区，但必须以“AI 建议”标记；用户修改后成为“已编辑”状态。
- 当 Agent Run 等待画布操作时，顶部出现明确任务提示：

  > 请确认角色主体范围。调整完成后选择“完成框选”，Agent 将继续拆分。

#### 完成与取消

- “完成框选”将结构化选区提交回原 Agent Run。
- “仅保存选区”保存当前状态但不继续 Agent。
- “取消本步骤”返回 Agent 对话并说明没有产生新资产。
- 关闭应用前自动保存未确认的选区草稿。

### 8.5 多结果选择模式

用于 2–8 个图片候选版本。

#### 卡片信息

- 大图缩略图。
- 版本编号。
- 生成时间。
- 模型与关键参数。
- Agent 的简短评价。
- 是否有异常，例如主体截断或风格偏差。

#### 操作

- 单选一个版本继续。
- 多选后进入对比。
- 请求 Agent 推荐。
- 对某个版本进行变体。
- 删除或隐藏不需要的版本。

如果 Agent Run 等待选择，用户点击“使用此版本”后直接恢复原 Run。选择事件应显示在对话中：

> 用户选择了“生成版本 C”作为下一步输入。

### 8.6 三视图编辑模式

#### 布局

默认同时显示三视图大图与三个裁切结果：

```text
┌────────────────────────────────────────────┐
│ 三视图原图：可缩放，显示 Front/Side/Back 框 │
└────────────────────────────────────────────┘
┌──────────────┬──────────────┬──────────────┐
│ 正面预览      │ 侧面预览      │ 背面预览      │
└──────────────┴──────────────┴──────────────┘
```

在工作区高度不足时，三张预览改为右侧浮动条或底部可折叠条。

#### 视图框

- 正面、侧面、背面分别使用颜色加文字标签区分。
- 颜色不是唯一标识；每个框始终显示视图名称和序号。
- 支持移动、缩放、锁定宽高比和数值输入。
- 支持自动检测视图边界。
- Agent 建议框显示虚线，用户确认后变为实线。
- 框越界、重叠异常或裁切尺寸过小时即时提醒。

#### 质量反馈

三张预览上显示一致性检查：

- 主体比例
- 头部/身体方向
- 关键配件一致性
- 是否被截断
- 背景是否干净
- 分辨率是否满足生成要求

问题以具体、可操作的语言展示：

> 侧视图中的武器比正视图明显偏高。可以调整裁切框，或让 Agent 只重做侧视图。

#### 继续条件

- 三个必需视图均存在。
- 用户确认所有框，或自动识别置信度达到设置阈值。
- 严重一致性错误需要用户确认后才能继续生成 3D。

### 8.7 3D 模型预览模式

#### 支持内容

- GLB 直接预览。
- 不直接预览 FBX；用户需要 FBX 时，由受控转换流程从当前 GLB 生成并保留原始 GLB。
- 旋转、平移、缩放、自动居中。
- 重置相机。
- 正、侧、背、顶等标准视角。
- 透视/正交相机切换。
- 环境光和背景切换。
- 线框模式。
- 材质、基础色、法线、粗糙度和金属度通道查看。
- 动画列表与播放控制（文件包含动画时）。

#### 信息面板

- 文件格式、文件大小。
- 顶点数、三角面数。
- 材质和贴图数量。
- 骨骼、动画数量。
- 模型边界尺寸。
- 来源图片和生成任务。
- 本地文件路径。

#### 操作

- 导出 GLB。
- 转换并导出 FBX。
- 打开所在文件夹。
- 保存标准角度截图。
- 请求 Agent 检查模型。
- 请求优化、减面或重新生成。

#### 异常提示

如果模型不能加载，预览区显示诊断信息和安全操作：

- 重新加载。
- 查看文件详情。
- 尝试转换副本。
- 打开原始文件位置。

不得覆盖原始模型以进行修复。

### 8.8 任务等待模式

长时间图片或 3D 任务运行时，工作区可以继续查看其他资产，不强制显示全屏等待。

当用户停留在任务输入资产上时，画布显示：

- 当前步骤。
- 百分比或阶段状态。
- 已用时间。
- 预计剩余时间（可用时）。
- 当前服务。
- 取消按钮。
- 切换到其他资产按钮。

任务完成后：

- 自动将结果加入资产列表。
- 如当前 Agent Run 正在等待该任务，则恢复 Agent Loop。
- 除非用户正在编辑未保存选区，否则自动聚焦新结果；否则仅提示结果已就绪。

## 9. 右侧 Agent 对话设计

### 9.1 面板结构

```text
┌───────────────────────────────┐
│ Agent 名称  会话标题  Run 状态 │
├───────────────────────────────┤
│ 对话消息与 Tool 卡片           │
│                               │
│                               │
├───────────────────────────────┤
│ 当前引用：@角色拆分v2  [×]     │
│ 输入消息、附件、快捷操作        │
│ [停止]                [发送]   │
└───────────────────────────────┘
```

### 9.2 对话上下文表达

Agent 必须在内部保存并恢复上下文，但首版不提供“当前上下文摘要”的查看或纠正入口。界面只展示当前显式引用的资产、选区、任务状态和待用户处理的动作；用户通过正常对话补充或修改目标。

### 9.3 输入区

输入区支持：

- 自然语言。
- 拖入图片或 GLB。
- 粘贴图片。
- `@` 引用项目资产、版本、选区和任务。
- `/` 调出常用命令。
- 自动附带当前画布资产和当前选区。
- Shift + Enter 换行，Enter 发送；可在设置中反转。

发送前显示当前引用，避免“这张图”指向错误对象。

### 9.4 消息与卡片类型

#### 普通回复

用于解释、建议、结果总结。宽度不超过对话面板的 88%，正文优先使用短段落。

#### 意图确认卡片

在存在歧义或置信度不足时显示：

```text
我理解你想：
将 @角色生成v3 中的角色单独拆出，并导出透明背景 PNG。

[确认并执行] [修改目标]
```

#### Agent Run 卡片

复杂任务以一个可折叠 Run 卡片组织，不把每轮 Tool 调用刷成大量零散气泡。

卡片头部：

- 任务目标。
- 状态。
- 已运行时间。
- 停止或继续。

展开内容：

```text
✓ 分析当前资产
✓ 生成正侧背三视图
✓ 自动识别视图区域
● 等待确认视图框
○ 生成 3D 模型
○ 检查模型
```

这里的列表是执行轨迹，而不是要求 Agent 在开始前一次性确定所有步骤。Agent 可以根据 Tool 结果新增、跳过或修改后续步骤，并说明原因。

#### Tool 调用卡片

每次 Tool 调用显示：

- 人类可读名称。
- 输入资产。
- 核心参数。
- 状态和耗时。
- 输出资产。
- 展开后的技术详情。

默认折叠完整参数和日志，成功后只保留一行摘要：

> 已生成三视图 · 2 分 18 秒 · 输出“三视图 v1”

#### 进度卡片

用于长任务：

- 阶段名称。
- 进度。
- 开始时间和已用时间。
- 取消能力。
- “后台运行”提示。

如果外部 API 不提供精确进度，应显示阶段式状态，不伪造百分比。

#### 审批卡片

用于外部上传、高成本调用、批量操作、覆盖或删除：

```text
即将生成 3D 模型

输入：正面 v1、侧面 v2、背面 v1
外部服务：Tripo3D
可能耗时：3–10 分钟
将上传：以上三张裁图

[确认执行] [调整参数] [取消]
```

审批卡片应持续存在，重新打开应用后仍可操作。

#### 用户选择卡片

用于版本、目标对象或视图选择。候选项可直接展示缩略图，并提供“在左侧放大查看”。

#### 画布操作卡片

用于要求用户在左侧完成交互：

```text
需要你确认三视图区域

我已自动标出正面、侧面和背面。请在左侧调整选框，完成后继续。

[前往画布] [使用当前选框继续] [取消任务]
```

#### 结果卡片

展示结果缩略图、模型快照、核心质量信息和后续建议。点击结果卡片应在左侧聚焦对应资产。

#### 错误恢复卡片

必须包含：

- 哪一步失败。
- 是否产生输出或费用。
- 已保存哪些结果。
- 可执行的恢复动作。

示例：

```text
3D 任务状态查询中断

外部任务 ID 已保存，模型生成可能仍在继续。

[重新查询] [稍后恢复] [停止本地等待]
```

### 9.5 运行中继续对话

Agent Run 运行期间，用户仍可以输入消息：

- 与当前任务相关的补充会进入当前 Run，例如“模型面数改成 5 万”。
- 明确取消、暂停或修改当前任务的消息优先处理。
- 无关的新任务应提示用户选择“暂停当前 Run 并开始新任务”或“加入待办”。
- 普通知识问答可以立即回答，但不打断后台任务。

## 10. Agent Loop 的可视化与控制

### 10.1 Run 状态

| 状态 | 用户界面表达 | 可用操作 |
|---|---|---|
| 理解中 | “正在理解你的目标” | 停止 |
| 执行中 | 当前 Tool 与执行轨迹 | 停止、折叠 |
| 等待审批 | 审批卡片高亮 | 确认、调整、取消 |
| 等待用户输入 | 问题或选择卡片 | 回复、选择、取消 |
| 等待画布操作 | 左侧进入指定模式 | 完成、仅保存、取消 |
| 等待后台任务 | 进度卡片 | 后台运行、取消 |
| 已暂停 | 显示暂停原因 | 继续、终止 |
| 已完成 | 结果摘要 | 查看结果、继续新请求 |
| 失败 | 错误与恢复建议 | 重试、改参数、终止 |
| 已中断 | 重开后发现未完成执行 | 恢复、检查状态、放弃 |
| 已取消 | 保留已产生结果 | 查看已有结果 |

### 10.2 多轮 Tool Calling 的展示原则

- 同一用户请求下的 Tool 调用聚合在同一 Run 卡片。
- 当前执行步骤始终可见。
- 已完成步骤默认折叠为简短轨迹。
- Agent 根据结果调整路径时，展示简短解释：

  > 侧视图一致性检查未通过，因此先只重做侧视图，再继续生成模型。

- 不展示模型内部思维过程，只展示目标、操作、依据、结果和下一步。
- 用户可以展开查看 Tool 参数与原始错误，但不默认暴露冗长日志。

### 10.3 暂停点

Agent Loop 在以下位置暂停：

1. 需要外部服务或费用审批。
2. 目标或参数有实质歧义。
3. 需要用户选择图片版本。
4. 需要用户调整矩形选框或三视图框。
5. 自动质量检查发现严重问题。
6. Tool 返回不可安全自动重试的错误。
7. 用户主动暂停或修改目标。

暂停时必须保存 Run，并在左侧和右侧同时显示恢复入口。

## 11. 典型使用流程

### 11.1 首次打开与导入图片

1. 用户进入最近项目页面或新建本地项目。
2. 选择项目目录。
3. 进入空白工作区。
4. 用户拖入图片，或在对话中说“分析这张图片”并添加附件。
5. 图片成为当前资产，左侧进入图片预览模式。
6. Agent 读取当前资产并回答或启动分析 Tool。
7. 结果保存在对话和资产版本中。

### 11.2 内容图与风格图合成 Prompt

1. 用户导入内容图与风格图。
2. 在对话中说：“分析这两张图，把内容图改成参考图的风格。”
3. Agent 确认两个附件的角色：内容、风格。
4. Agent Loop 分析内容、分析风格并合成 Prompt。
5. 左侧显示双图对比和可编辑 Prompt 参数抽屉。
6. 如果用户只要求 Prompt，Run 在此完成。
7. 如果用户同时要求生成图片，Agent 在调用外部生成服务前按审批策略继续或暂停。
8. 多个结果进入多结果选择模式。

### 11.3 框选拆分

1. 用户在图片预览中说：“把人物和武器分别拆出来。”
2. Agent 尝试建议两个选区。
3. 左侧进入矩形框选模式，并显示“人物”“武器”两个命名选框。
4. Agent Run 进入“等待画布操作”。
5. 用户调整人物框和武器框的位置与大小。
6. 点击“完成框选”。
7. Agent Loop 继续调用拆分工具，生成两个透明背景资产。
8. 左侧切换到拆分结果，右侧显示结果卡片。

### 11.4 从角色图到 3D 模型

用户输入：

> 用当前角色生成正侧背三视图，检查一致性，有问题就修复，没问题后生成 5 万面以内的 GLB。

交互过程：

1. Agent 建立一个复杂 Run，并确认当前角色资产。
2. 生成三视图。
3. 自动检测正面、侧面、背面区域。
4. 执行一致性检查。
5. 如果检测结果可靠，按审批策略进入下一步；如果框或视图有问题，暂停。
6. 用户在三视图编辑模式确认或调整。
7. Agent 恢复同一个 Run，裁切三张视图。
8. 在提交外部 3D 服务前显示审批卡片。
9. 用户确认后创建后台任务。
10. 用户可以浏览其他资产或关闭应用。
11. 任务完成后 Agent Run 恢复并检查模型。
12. 左侧进入 3D 预览模式，右侧总结面数、材质、文件大小和异常。

### 11.5 只重做单个视图

1. 用户在三视图模式说：“侧面武器不对，只重新做侧面。”
2. Agent 将“侧面 v1”作为目标，将正面和背面作为一致性参考。
3. 只调用单视图重生成。
4. 新结果与旧侧面并排展示。
5. 用户选择新版本后，三视图组合更新为“正面 v1 / 侧面 v2 / 背面 v1”。
6. 所有历史版本保留。

### 11.6 模型预览与导出

1. 用户打开 GLB 或说“看看刚才的模型”。
2. 左侧进入 3D 预览。
3. 用户说“导出 FBX 并打开目录”。
4. Agent Loop 调用转换 Tool。
5. 转换完成后调用本地打开目录操作。
6. 对话显示输出路径和结果卡片。

### 11.7 应用关闭与恢复

1. 用户在 Tripo3D 运行中关闭应用。
2. 下次启动后进入最近项目。
3. 工作区恢复到上次资产与画布视角。
4. 右侧恢复历史消息和 Run 卡片。
5. 应用检查外部任务状态。
6. 如果任务仍运行，继续显示进度；如果已完成，恢复 Agent Loop 并处理结果。
7. 如果上次停在选区编辑，恢复未确认选区草稿和“完成框选”提示。

## 12. 项目、资产与版本交互

### 12.1 资产面板

按类型分组：

- 输入图片
- 生成图片
- 拆分元素
- 三视图与裁图
- 3D 模型
- 导出文件

每个资产显示：

- 缩略图或模型快照。
- 名称和版本。
- 当前标记。
- 生成来源。
- 正在使用或被任务引用状态。

### 12.2 资产关系

版本视图使用简单的父子关系，不默认展示复杂节点图。用户选中资产时，显示：

```text
原始角色图
  → 风格化生成 v3
    → 人物拆分 v2
      → 三视图 v1
        → GLB v1
```

支持：

- 设为当前资产。
- 查看父版本。
- 创建新分支。
- 比较兄弟版本。
- 查看生成参数。
- 在对话中引用。

### 12.3 删除与隐藏

- “隐藏”用于减少界面噪声，可随时恢复。
- “移到回收站”是可恢复删除。
- 删除正在被 Agent Run 或后代资产引用的版本时，必须提示影响。
- 不提供无提示永久删除。

## 13. 状态、异常与恢复设计

### 13.1 保存状态

| 状态 | 展示 |
|---|---|
| 已保存 | 顶部轻量勾选图标 |
| 正在保存 | 小型进度指示 |
| 未保存 | 项目名旁圆点 |
| 保存失败 | 明确错误和“重试保存” |
| 只读 | 显示只读原因和另存为入口 |

聊天、选区和 Agent Run 应增量保存，不依赖用户手动点击保存。

### 13.2 网络异常

本地应用不等于完全离线。外部 AI 服务不可达时：

- 本地浏览、裁切、模型预览和项目管理仍可使用。
- Agent 对话若使用本地模型可继续。
- 依赖外部 API 的 Tool 标记为不可用。
- 正在等待的任务保留外部任务 ID。
- 恢复网络后可以重新查询，不自动重复创建付费任务。

### 13.3 Tool 错误

错误分为：

- 输入无效
- API 未配置
- 外部服务拒绝
- 超时
- 本地文件不存在
- 文件格式不支持
- 任务取消
- 未知异常

面向用户的错误信息必须说明：

1. 失败对象。
2. 失败步骤。
3. 已有结果是否保留。
4. 是否可以安全重试。
5. 推荐操作。

### 13.4 应用崩溃或强制关闭

重新打开后：

- 未完成 Run 标为“已中断”。
- 长任务先查询真实外部状态。
- 本地可幂等操作允许用户一键恢复。
- 可能重复扣费的操作不能直接重跑。
- 未确认的框选和参数草稿恢复。

### 13.5 取消

取消分为：

- 停止当前 Agent 推理。
- 取消本地 Tool。
- 请求取消外部任务。
- 仅停止等待但不取消外部任务。

界面应解释这些行为的差异。若外部服务不支持取消，按钮文本应为“停止等待”，并说明任务可能仍在继续。

## 14. 视觉风格

### 14.1 风格定位

视觉方向为“专业创作工作台”，关键词：

- 克制
- 精确
- 沉浸
- 高信息密度
- 资产优先
- AI 执行透明

默认使用深色主题，使图片和 3D 模型成为焦点。界面不使用大面积渐变、玻璃拟态或装饰性插画。AI 能力通过执行卡片和状态变化体现，不依赖机器人头像或炫光效果。

### 14.2 色彩 Tokens

#### 深色主题

| Token | 建议值 | 用途 |
|---|---|---|
| `bg-canvas` | `#0B0D10` | 图片与 3D 画布背景 |
| `bg-app` | `#101318` | 应用主背景 |
| `bg-panel` | `#161A21` | 导航、Agent 面板 |
| `bg-elevated` | `#1D222B` | 卡片、浮层 |
| `border-subtle` | `#2A303B` | 普通边界 |
| `border-strong` | `#3A4351` | 强调边界 |
| `text-primary` | `#F2F4F7` | 主要文本 |
| `text-secondary` | `#AAB2C0` | 次要文本 |
| `text-muted` | `#727D8E` | 辅助信息 |
| `accent-primary` | `#7C83FF` | 主操作与焦点 |
| `accent-hover` | `#9298FF` | 主操作悬停 |
| `success` | `#45C98A` | 成功 |
| `warning` | `#E5AA4F` | 警告和等待 |
| `danger` | `#EF6671` | 失败和危险操作 |
| `info` | `#55A7F5` | 信息与运行中状态 |
| `selection-overlay` | `rgba(11,13,16,.62)` | 矩形选框外遮罩 |

视图框建议：

- 正面：蓝色 `#55A7F5`
- 侧面：紫色 `#A77BF3`
- 背面：橙色 `#E5AA4F`

必须同时显示文本标签，不能只靠颜色识别。

### 14.3 字体

优先使用系统 UI 字体栈：

```text
Inter / Segoe UI / PingFang SC / Microsoft YaHei / sans-serif
```

| 类型 | 字号/行高 | 字重 |
|---|---|---|
| 页面标题 | 20/28 px | 600 |
| 区域标题 | 16/24 px | 600 |
| 正文 | 14/22 px | 400 |
| 紧凑正文 | 13/20 px | 400 |
| 辅助信息 | 12/18 px | 400 |
| 代码与路径 | 12/18 px | 400，等宽 |

对话正文使用 14 px，Tool 卡片参数使用 12–13 px。避免在高密度界面中大量使用 11 px 以下文字。

### 14.4 间距

采用 4 px 基础网格：

- `space-1`: 4 px
- `space-2`: 8 px
- `space-3`: 12 px
- `space-4`: 16 px
- `space-5`: 20 px
- `space-6`: 24 px
- `space-8`: 32 px

卡片内边距默认 12 px，对话普通消息 12–16 px，主面板内边距 16 px。

### 14.5 圆角与阴影

| 元素 | 圆角 |
|---|---:|
| 按钮、输入框 | 6 px |
| 卡片 | 8 px |
| 对话气泡 | 10 px |
| 浮层与菜单 | 10 px |

深色主题中主要用边框和背景层级区分，不依赖大面积阴影。浮层阴影建议低透明度、短距离。

### 14.6 图标

- 使用同一套线性图标。
- 默认 16 px，主导航 20 px。
- 图标必须有 Tooltip 或文本标签。
- 状态图标不使用 Emoji。
- “生成”“重试”“继续”等不同动作不能使用同一个模糊图标。

### 14.7 动效

- 面板展开：160–220 ms。
- 卡片状态变化：120–180 ms。
- 画布切换：轻微淡入，不做位移较大的转场。
- 进度仅在真实运行时显示。
- 支持“减少动态效果”系统设置。

## 15. 响应式设计

### 15.1 桌面优先范围

| 宽度 | 布局 |
|---|---|
| ≥ 1600 px | 标准双栏，Agent 420–480 px |
| 1280–1599 px | 标准双栏，Agent 360–420 px |
| 1024–1279 px | Agent 可覆盖式展开，工作区保持最小宽度 |
| < 1024 px | 进入紧凑模式，仅保证浏览和轻量对话，不承诺完整画布编辑体验 |

### 15.2 窄窗口策略

- 优先保证画布可用宽度。
- Agent 面板改为右侧覆盖抽屉。
- 资产导航折叠为图标。
- 参数区改为底部 Sheet。
- 三视图三个裁切预览允许横向滚动。
- 3D 信息面板进入抽屉。

移动设备不是首版目标，不设计移动端复杂框选和 3D 生产流程。

## 16. 可访问性

### 16.1 键盘操作

核心操作应支持：

- Tab 在可交互元素间移动。
- Enter/Space 触发按钮。
- Esc 关闭弹层或退出当前画布工具。
- Ctrl+Z / Ctrl+Shift+Z 撤销与重做。
- `+` / `-` 缩放画布。
- `0` 适应画布。
- 空格拖动画布。
- Delete 删除当前选区点或对象，执行前符合删除策略。
- Ctrl+Enter 完成当前画布操作。

### 16.2 焦点管理

- Agent 请求用户进行画布操作时，焦点移动到画布模式标题，而不是直接落到画布内部。
- 对话新增结果不抢夺正在编辑画布的焦点。
- 弹窗关闭后焦点返回触发元素。
- 恢复应用时，焦点默认落在主工作区标题，不自动进入对话输入框。

### 16.3 色彩和文本

- 正文与背景对比度不低于 WCAG AA。
- 重要状态同时使用图标、文字和颜色。
- 选区必须有边框、标签与遮罩。
- 错误提示不使用纯红色小字作为唯一反馈。
- 用户可调整 UI 缩放比例和对话字号。

### 16.4 画布替代操作

对无法使用精细拖拽的用户提供：

- 选框 X、Y、宽、高数值输入。
- 方向键移动选框，Shift 加速。
- 预设视图区域。
- 自动选择主体。
- 清晰的撤销和重置。

## 19. 文案规范

### 19.1 操作名称

- 使用“生成三视图”，不使用“执行 Multiview Tool”。
- 使用“生成 3D 模型”，不使用“提交 Tripo 任务”作为主按钮。
- 使用“完成框选并继续”，明确动作与后果。
- 使用“停止等待”，区分于无法真正取消的外部任务。

### 19.2 状态文案

推荐：

- 正在分析图片
- 等待确认选区
- 正在生成三视图
- 3D 任务已提交，正在等待结果
- 模型已生成，正在检查文件
- Agent Run 已暂停

避免：

- Loading
- Thinking
- Error 500
- 未知失败，请稍后再试

### 19.3 Agent 语气

- 简洁、专业、行动导向。
- 先说明结果，再说明过程。
- 需要用户操作时只提出一个清晰主问题。
- 不把自动建议描述成确定事实。
- 不使用过度拟人化或夸张表达。

## 20. 验收标准

### 20.1 全局与布局

- 在 1440 × 900 下，左侧画布、右侧 Agent 和全局状态同时可见，无横向滚动。
- Agent 面板宽度可在 360–520 px 之间调整并恢复。
- 工作区可用宽度不低于 680 px。
- 用户可折叠 Agent 面板和参数抽屉。
- 重开应用后恢复上次项目、面板尺寸和工作区模式。

### 20.2 对话与上下文

- 每轮对话能引用上一轮已经确定的目标、资产和约束。
- 关闭并重开应用后，对话消息、Tool 卡片和结果引用完整恢复。
- “这张图”“刚才的结果”“第二个版本”等引用在界面中有明确解析对象。
- 发送消息前能看到自动附加的当前资产和选区。

### 20.3 Agent Loop

- 一次用户请求可在同一个 Run 中连续执行多个 Tool。
- 每个 Tool 的当前状态、输入和结果可查看。
- Run 在审批、用户选择和画布操作处正确暂停。
- 用户完成暂停点后，恢复原 Run，不创建割裂的新任务。
- 用户可以停止 Run；停止后已生成资产仍可查看。
- 应用重开后，等待中的 Run 可恢复、重试或终止。
- 不展示模型内部思维过程，只展示可理解的操作轨迹。

### 20.4 图片与框选

- 图片支持缩放、平移、适应画布和 100% 查看。
- 框选坐标以原图像素保存，缩放后位置不漂移。
- 支持矩形框、清除、撤销和重做。
- Agent 建议选区与用户确认选区视觉上可区分。
- 用户关闭应用后，未确认选区草稿可恢复。
- 完成框选后结果能回传并继续等待中的 Agent Run。

### 20.5 三视图

- 可编辑正面、侧面、背面三个独立框。
- 每个框同时使用颜色和文字标签。
- 调整框后，三个裁切预览实时更新。
- 自动检测结果以建议状态呈现。
- 视图缺失、越界和严重一致性问题有明确提示。
- 用户可只重做一个视图而保留其他视图版本。

### 20.6 模型预览

- 可加载并预览本地 GLB。
- 可将当前 GLB 转换并导出为 FBX，转换过程不覆盖原始 GLB；首版不直接预览 FBX。
- 支持旋转、缩放、平移、重置和标准视角。
- 支持线框与主要材质通道查看。
- 能展示文件大小、面数、材质、贴图和动画等可用元数据。
- 导出后能显示完整本地路径并打开所在文件夹。

### 20.7 状态与恢复

- 外部 API 离线时，本地浏览、裁切、预览和项目操作仍可使用。
- 长任务在用户浏览其他资产时继续运行。
- 重新打开应用后能查询已保存的外部任务 ID，不重复创建任务。
- 所有错误卡片说明失败步骤、已有结果、费用影响和恢复方法。
- 不支持取消的外部任务使用“停止等待”，不误导用户。

### 20.8 视觉与可访问性

- 主要正文对比度满足 WCAG AA。
- 所有重要状态不只依赖颜色。
- 主流程可使用键盘完成，精细画布操作提供数值输入替代。
- 焦点状态清晰，弹窗和抽屉符合预期焦点顺序。
- 用户开启减少动态效果后，无非必要大幅动画。
- 所有仅图标按钮均提供可访问名称和 Tooltip。

## 21. 设计交付顺序建议

1. 先完成应用框架、工作区和 Agent 面板的低保真交互原型。
2. 验证三个关键闭环：
   - 对话启动图片分析并展示结果。
   - Agent 暂停等待框选，用户完成后继续。
   - 复杂 Run 经三视图、审批、长任务后恢复并展示模型。
3. 确认 Run 卡片、Tool 卡片和恢复卡片的信息层级。
4. 完成图片画布与三视图编辑器的高保真交互。
5. 完成 3D 预览和导出界面。
6. 统一设计 Tokens、组件状态和可访问性。
7. 以本文件验收标准进行可用性走查。

## 22. 首版设计边界

首版包含：

- 本地项目与最近项目。
- 左侧工作区、右侧 Agent 的双栏结构。
- 持久对话和可恢复 Agent Run。
- 多轮 Tool Calling 的执行轨迹。
- 图片预览、对比和矩形框选。
- 三视图生成结果和裁切框编辑。
- 图片候选版本选择。
- GLB 模型预览、检查以及 FBX 转换导出。
- 外部服务审批、任务进度、失败恢复。

首版不包含：

- 云端账号与团队协作。
- 多人实时编辑。
- 手机端完整生产体验。
- 复杂节点式工作流编辑器。
- 网页内建模或骨骼编辑。
- 多 Agent 并行协作界面。
- 插件市场与公开分享。

首版最终要验证的不是“功能入口是否齐全”，而是用户能否自然地完成以下循环：

> 通过对话表达目标 → 看懂 Agent 正在做什么 → 在左侧完成必要判断与精细操作 → 让 Agent 继续执行 → 获得可追溯、可恢复的图片或模型资产。
