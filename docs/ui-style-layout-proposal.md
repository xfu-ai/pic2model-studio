# FormWeaver Studio 前端 UI 系统评审与风格布局方案

> 评审日期：2026-07-30
> 评审范围：工作区六个创作页签、资产、任务、导出，以及全局 Shell / Agent 面板
> 证据来源：用户提供的 9 张 3851 × 2099 桌面端截图，以及当前前端布局、Token 与组件结构
> 本文只定义视觉与布局方向，不包含本轮代码改动。

## 1. 结论

当前版本已经具备一套可靠的暗色专业工具基础：主画布突出、工作流完整、状态色基本统一、Phosphor 图标风格一致。问题主要不在单个控件，而在整体层级和空间分配：

1. Agent 是核心工作面板，必须默认持续可见；真正的问题不是空间是否被填满，而是各页面缺少统一的主题、构图和视觉重心规则。
2. 六个创作页没有共享稳定的“页面骨架”，标题、参数、主操作、状态和结果位置持续变化。
3. 画布型页面偏拥挤，资产 / 任务 / 导出页又过度稀疏，密度缺少统一基准。
4. 页面大量使用 10–13 px 文本、灰色按钮和嵌套面板，信息可以看见，但扫描成本偏高。
5. 任务、导出、3D 空态缺少明确的视觉中心，容易让用户误判为“页面没加载”。

建议保留现有暗色底色与紫色品牌强调，升级为一套更克制的创作工作台风格：

**Midnight Foundry / 深夜铸造台**

- 大画布、低干扰、清晰的单一主操作。
- 紫色表示用户当前操作，青绿色表示 AI 生成或已连接状态。
- 面板主要靠间距、分组和细分隔线区分，减少“卡片套卡片”。
- Agent 作为独立核心栏永久保留；Agent 左侧工作区根据任务采用沉浸、编辑、精调、集合或工具型构图，允许有意留白。

## 2. 审计范围与用户目标

核心用户需要在同一个桌面工作台中完成：

`图片 → Prompt → 候选图 → 建模目标 → 三视图 → 3D → 导出`

设计必须优先保障：

- 长时间工作时快速定位当前素材、当前步骤和下一步。
- 画布操作、候选比较与参数调整不互相抢占空间。
- 异步任务离开当前页后仍可追踪，失败后能恢复。
- 支持跳步和回看，不把流程误做成强制向导。
- 在 1280–4K Windows 桌面与 125% / 150% 缩放下保持可读。

## 3. 共性优点

- 暗色工作台适合图片和 3D 内容，素材本身有足够视觉主导权。
- 左侧一级导航只有工作区、资产、任务、导出，信息架构基本正确。
- 图片生成页已经形成“参数区 + 结果区”的清晰主次，是当前最成熟的页面。
- 目标提取、三视图已把复杂任务拆成来源、画布、输出三个阶段。
- Token 已覆盖颜色、间距、圆角、尺寸、焦点和降动效，可在现有基础上演进。
- 图标体系统一，状态色包含成功、警告、危险，具备设计系统基础。

## 4. 跨页面主要问题

### P0：结构问题

1. **Agent 左侧工作区缺少系统性的构图规则**
   - Agent 默认持续可见是正确的产品定位，不应自动折叠或被页面参数替换。
   - 目标提取和三视图的信息列较多，需要建立清晰的画布主次，但仍应保留 Agent。
   - 任务与导出页的问题不是“没有铺满”，而是内容贴边、视觉锚点不足，留白显得偶然。
   - 3D 页面可以保留大面积负空间，但无模型、加载或失败时必须有明确视觉中心。
   - 页面应共享同一种视觉语言，同时根据任务性质选择不同密度，不能所有页面都套同一张网格。

2. **横向流程页签像“网站导航”，不像生产流程**
   - 六个项目等权展示，缺少已完成、当前、可继续、需注意等状态。
   - “图片主页”与五个生产步骤等权，降低流程感。
   - 页面可跳转是正确的，但视觉上无法快速理解产物链路。

3. **页面骨架不统一**
   - 有的页面标题在内容顶部，有的标题与操作挤在工具条。
   - 主按钮有时在左栏底部、有时在右栏底部、有时在顶栏。
   - 状态信息分散在卡片、底栏、Agent 消息和任务中心。

### P1：可用性问题

1. **密度两极分化**
   - Prompt、目标提取、三视图过密。
   - 3D、任务、导出过疏。

2. **按钮层级不够清楚**
   - 大量相同灰度按钮并列，主要、次要、危险、导航动作差异不足。
   - 紫色按钮出现频率偏高，削弱真正主操作的强调度。

3. **滚动容器过多**
   - 页面、左右栏、Agent 各自滚动，容易失去当前位置。
   - Prompt 页面长内容尤其明显。

4. **中英文与术语不统一**
   - 页面标题、说明、按钮和 Agent 内容存在中英文混用。
   - “生成 3D / 3D 模型生成 / 输出并准备 3D”等表述需要统一动作语义。

### P1：可访问性风险

以下是截图可见风险，不代表完整 WCAG 检测结论：

- 10–12 px 辅助文字较多，4K 截图缩放后明显难读。
- 部分灰字与深色背景的对比度可能不足，需要实际测色确认。
- 一些按钮高度约 30–36 px，连续精细操作时点击容错偏低。
- 三视图选区依赖蓝 / 绿 / 橙颜色，需要同时保留编号、名称和不同线型。
- 图标按钮较多，需逐项确认可见 Tooltip、键盘焦点与可访问名称。
- 不能从截图确认键盘顺序、焦点陷阱、实时状态播报和 200% 缩放行为。

## 6. 建议的全局布局

### 6.1 新 Shell：Agent 永久常驻

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 项目 / 当前资产                         自动保存  本地服务  搜索  设置      │ 48
├──────┬───────────────────────────────────────────────────────┬───────────────┤
│      │ 工作区标题 + 流程状态 + 页面级主操作                  │ AI Agent      │ 48
│ 主导 │───────────────────────────────────────────────────────│───────────────│
│ 航   │                                                       │ 会话 / 运行   │
│ 56   │            自适应主画布 / 主列表 / 表单               │ 工具 / 结果   │ 360–420
│      │                                                       │ 输入区        │
│      │                                                       │               │
├──────┴───────────────────────────────────────────────────────┴───────────────┤
│ 后台任务状态 / 当前操作提示 / 快捷键                                           │ 28
└──────────────────────────────────────────────────────────────────────────────┘
```

不可变约束：

- Agent 是独立核心栏，应用启动和页面切换后都默认持续可见。
- 页面参数、结果或任务详情不能替换 Agent，也不能导致 Agent 自动收起。
- Agent 宽度默认 380 px，可在 340–480 px 之间拖动；用户宽度偏好持久化。
- Agent 标题、会话、工具执行、图片结果和输入区保留现有完整能力。

工作区构图规则：

- 左侧一级导航保留，建议宽 56 px。
- 顶栏建议高 48 px，项目名与当前资产使用单行层级。
- Agent 左侧区域使用 `minmax(0, 1fr)` 承载页面舞台，但内容可以设置合理最大宽度并有意留白。
- 画布页可使用“紧凑步骤栏 + 弹性画布 + 紧凑结果栏”，画布始终是视觉重心。
- 列表和表单页不要求铺满；内容应围绕中央、黄金分割线或明确对齐轴形成稳定构图。
- 不增加无意义卡片、统计数字或装饰面板来填空。
- 留白必须服务于聚焦、阅读、素材展示或层级分隔，不能只是内容停在左上角后留下的剩余区域。
- 主操作固定在页面标题栏右侧或页内操作区底部；一个视图只出现一个高强调主按钮。

### 6.2 页面构图原型

| 原型 | 构图方式 | 适用页面 |
|---|---|---|
| 沉浸舞台 | 素材或模型居中，周围保留低干扰负空间，工具悬浮在边缘 | 图片主页、3D |
| 编辑器 | 参数和结果形成 32:68 或 38:62 的明确主次，内容纵向对齐 | 图像生成、参考 Prompt |
| 精调画布 | 左工具、中央画布、右结果形成紧凑三段，中央面积和明度最高 | 目标提取、三视图 |
| 集合浏览 | 网格或列表有最大卡片宽度和稳定节奏，详情按选择出现 | 资产 |
| 工具面板 | 720–960 px 内容主体居中或偏黄金分割线，辅助信息轻量陪衬 | 任务空态、导出 |

这些原型决定“哪里应该紧凑、哪里应该呼吸”。目标不是把每块空间变成内容，而是让视觉重心稳定、留白有意图、操作路径清楚。

### 6.3 留白判断标准

可以保留：

- 素材或模型周围的舞台空间。
- 阅读表单两侧的舒适边距。
- Agent 与主工作区之间的视觉缓冲。
- 未选择对象时用于展示空态、引导或项目概览的中心区域。

需要修正：

- 内容全部贴在左上角，右下方没有视觉锚点。
- 页面主体只有一排按钮，其余区域没有标题、状态或空态。
- 相邻页面对相同信息使用完全不同的宽度和对齐。
- 空白导致用户怀疑页面未加载或功能缺失。

### 6.4 流程导航

把现有六个等权页签改成两层：

1. `图片主页`作为工作区 Home，不参与步骤编号。
2. 五个生产步骤显示为：

`1 Prompt → 2 生图 → 3 提取 → 4 三视图 → 5 生成 3D`

每一步支持四种状态：

- `已完成`：实心圆 + 对勾。
- `当前`：紫色强调 + 页面名称。
- `可进入`：普通文字，可自由跳转。
- `需处理`：警告点 + 简短原因。

不使用“锁定”状态，避免误导用户必须线性执行。

## 7. 风格系统

### 7.0 主题概念：Midnight Foundry

这套界面应当更像创作者的数字暗房和建模工作台，而不是普通后台管理系统。

**材质**

- Shell 使用深石墨色哑光表面，面板之间主要靠明度和细分隔线区分。
- 画布接近纯黑，避免影响图片、透明背景和模型材质判断。
- 浮层只在真正悬浮的工具、审批和菜单上使用阴影。

**光感**

- 紫色是用户控制：当前步骤、主操作、选中和键盘焦点。
- 青绿色是 AI 痕迹：自动分析、生成结果、本地服务和 Agent 工具运行。
- 状态色只用于状态，不把成功绿、警告橙当作普通装饰色。
- 选中素材可以使用非常克制的柔光边缘，避免大面积高饱和背景。

**节奏**

- 大画布页安静、宽松，让素材成为主角。
- 参数页紧凑但不拥挤，依靠基线、组间距和标题层级组织信息。
- 任务、资产等集合页保持稳定的行高和卡片比例，形成可快速扫描的节奏。
- Agent 保持同一视觉密度，不因切换页面改变宽度或样式。

**识别元素**

- 流程导航使用一条细紫色进度轨迹，完成节点带青绿色状态点。
- 画布工具使用半透明深色浮条，与主体面板形成轻重对比。
- 图片、三视图和 3D 结果共享一致的“受管资产”边框、名称和状态表达。
- 延续 Phosphor 线性图标，不混用实心、拟物或系统 Emoji。

**明确避免**

- 不把所有内容都放进独立卡片。
- 不使用大面积紫色渐变充当背景。
- 不用无业务意义的指标卡、插画或装饰图形填补空白。
- 不让不同页面看起来像来自不同套组件库。

### 7.1 色彩

现有颜色方向正确，建议只做层级整理：

| Token | 建议值 | 用途 |
|---|---|---|
| `bg-canvas` | `#090C11` | 图片 / 3D / 选区画布 |
| `bg-app` | `#0E1218` | 应用底色 |
| `bg-panel` | `#141A23` | 导航、Agent、页内侧栏 |
| `bg-elevated` | `#1A2230` | 输入、浮层、选中行 |
| `border-subtle` | `rgba(255,255,255,.08)` | 普通分隔 |
| `border-strong` | `rgba(255,255,255,.16)` | 强分隔、悬停 |
| `text-primary` | `#F4F7FB` | 标题与主要正文 |
| `text-secondary` | `#A7B2C2` | 说明与元数据 |
| `text-muted` | `#748196` | 非关键辅助信息 |
| `accent` | `#857BFF` | 当前选择、主操作、焦点 |
| `ai-accent` | `#48D4C6` | AI 生成、连接、自动处理 |
| `success` | `#45D483` | 完成 |
| `warning` | `#F0B75A` | 等待、需确认 |
| `danger` | `#FF6B78` | 失败、危险动作 |

不建议在普通容器上大面积使用紫色背景。紫色只保留给当前步骤、主按钮、选中边框和焦点。

### 7.2 字体与字号

为保证离线桌面一致性，不引入网络字体：

`Inter, "Microsoft YaHei UI", "Noto Sans SC", system-ui, sans-serif`

| 层级 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 22 / 30 | 650 |
| 区域标题 | 16 / 24 | 600 |
| 正文 / 控件 | 14 / 22 | 400–500 |
| 辅助信息 | 12 / 18 | 400 |
| 极少数标记 | 11 / 16 | 500 |

不再使用 10 px 正文；英文 Eyebrow 只用于页面类别，不在每个卡片重复。

### 7.3 间距、圆角与层级

- 基础间距：`4 / 8 / 12 / 16 / 24 / 32`。
- 控件高度：普通 36 px，主操作和高频输入 40 px。
- 圆角：控件 8 px，面板 12 px，浮层 14 px。
- 阴影只用于弹窗、拖拽对象和浮层；常驻面板只用背景差与细分隔线。
- 内容区默认边距 20–24 px；紧凑面板内部 16 px。
- 列表优先使用行分隔，不让每一项都变成厚重卡片。

### 7.4 按钮语义

- `Primary`：每个视图最多一个，紫色实心。
- `Secondary`：描边或轻表面，用于可逆的辅助动作。
- `Ghost`：工具条图标和低频动作。
- `Danger`：红色文字 / 描边，和主操作分开。
- `Split button / More`：批量容纳“恢复、清空、Legacy、另存”等低频动作。

## 8. 各页面目标布局

### 图片主页

- 页面标题栏：资产名、版本、尺寸、格式；右侧只保留“导入”和“截屏”。
- 画布工具条改为左上浮层，缩放工具保留右下浮层。
- “提取目标 / 参考 Prompt / 生成变体 / 三视图 / 3D”改为画布下方的下一步动作条。
- Agent 默认持续可见；图片画布自动适应 Agent 左侧全部可用空间。

### 参考 Prompt

- 左侧 280 px 为参考素材轨道，内容图与风格图用折叠区或可交换缩略图呈现。
- 中央为内容、风格、合并三个分段编辑器，默认只展开当前段。
- 合并结果固定在底部结果区，避免必须滚到底才能继续。
- “重新分析”做成行级次要动作；保存采用自动保存 + 状态提示。

### 图像生成

- 左侧 320 px：Prompt、语言、数量、比例、模型、高级参数。
- 中央：选中图大预览；底部为候选胶片和版本切换。
- 生成中在预览中心显示进度，不额外制造状态卡片。
- 选择候选后主操作从“生成”切换为“使用此图”。

### 目标提取

- 左侧 260 px：`1 来源 → 2 方法 → 3 拆解类型`。
- 中央：全尺寸交互画布，缩放与选择工具悬浮。
- 页内紧凑结果栏：选区尺寸、生成状态、目标预览、进入三视图；Agent 继续独立常驻。
- `x / y / width / height` 默认折叠到“高级精确选区”。

### 三视图

- 中央画布占首要空间。
- 正 / 侧 / 背结果改为画布底部横向胶片，可点击放大和替换。
- 选区颜色同时使用编号 `1 / 2 / 3` 与名称，避免只靠颜色识别。
- 质量检查、目标面数、确认与输出收拢到页内紧凑结果栏；Agent 继续独立常驻。

### 3D 模型

- 视口内左上：视图、线框、材质、背景。
- 视口内右上：截图、适应、重置相机。
- 视口中央必须呈现明确的加载、失败或空态，不能只显示大块灰黑。
- 模型统计、任务进度、优化、格式与导出放入视口侧栏或底部抽屉，不占用 Agent。
- “导出 FBX”属于结果动作，不应和相机工具混在同一排。

### 资产

- 固定头部：搜索、类型、来源、排序、视图密度。
- 图片 / 三视图 / 模型使用网格；Prompt / JSON / 日志使用紧凑列表。
- 卡片只显示缩略图、名称、类型和关键元数据；详细 Prompt 放到资产页内详情抽屉。
- 支持当前资产标识、批量选择与最近使用分组。

### 任务

- 无选中任务时使用约 920–1100 px 的居中任务列表，周围留白用于降低扫描压力。
- 选中任务后自然展开为约 42% 列表 + 58% 详情；这是状态驱动的展开，不是为了铺满页面。
- 顶部统计改为可点击筛选 Chip：`进行中 0 / 需处理 3 / 已完成 27`。
- 列表行显示状态、任务名、耗时、来源、最新动作。
- 详情区显示时间线、输入输出、错误摘要、重试和“继续到目标提取”等恢复动作。
- Agent 继续常驻；任务列表与详情构成稳定的主从关系。需要解释失败时，可把选中任务上下文直接发送给 Agent。

### 导出

- 标题改为“导出项目”，全中文。
- 使用约 760–920 px 的居中主面板，建立明确而安静的视觉中心。
- 四段式单页表单：`导出内容 → 格式 → 保存位置 → 摘要`，不为了占宽强拆成多列。
- 默认主操作为“导出项目包”；最近使用的格式与位置可记忆。
- Legacy 导入导出放到折叠的“兼容旧版本”区域。
- 有最近导出记录时在主面板下方轻量展开；无记录时保留留白，不添加占位卡片。

## 9. 状态与动效

- 所有异步任务使用同一状态条：等待、运行、需确认、成功、失败。
- 页面内状态与底部任务栏共享同一任务名称和进度，不重复不同文案。
- 生成完成时只做 160–220 ms 的边框 / 背景过渡，不使用强烈弹跳。
- 候选切换、面板切换使用 120–160 ms 淡入与位移。
- 完整支持 `prefers-reduced-motion`。
- 页面离开后任务继续，返回时恢复素材、滚动、选区、页内面板和 Agent 会话。

## 10. 响应式与桌面缩放

| 可用宽度 | 布局策略 |
|---|---|
| ≥ 1600 px | 左导航 56 + 自适应主区 + 常驻 Agent 380–420 |
| 1280–1599 px | 常驻 Agent 340–380；复杂页侧栏 240–260 |
| 1024–1279 px | 常驻 Agent 300–340；页内次要面板改抽屉或底部栏 |
| < 1024 px | 保留最小 Agent 280；进入紧凑浏览模式并提示复杂画布的推荐宽度 |

必须验证 Windows 100%、125%、150% 缩放，以及浏览器等效 200% 文本缩放下：

- 不出现隐藏主按钮。
- 不出现无法到达的内部滚动区域。
- Agent 始终可见；拖动宽度后工作区能即时重排，不遮挡主操作。
- 表单标签不依赖 Placeholder。

## 11. 落地优先级

### Phase A：先建立统一骨架

1. 新增 `WorkspaceHeader`、`WorkflowProgress`、`WorkspaceSplitLayout`、`StatusStrip`。
2. 固化 Agent 常驻栏契约：默认可见、可调宽、跨页面保持会话和宽度。
3. 建立沉浸画布、参数结果、三栏画布、列表详情、表单摘要五种自适应模板。
4. 统一按钮、输入、分段控件、空态、状态条。
5. 收敛 Token，消除页面内硬编码字号、圆角和状态颜色。

### Phase B：先改高收益页面

1. 任务中心。
2. 导出。
3. 3D 空态 / 加载 / 结果。
4. 图片主页的自适应画布。

这些页面结构问题最明显，改动后能立刻建立新版风格基线。

### Phase C：重构复杂画布

1. 目标提取。
2. 三视图。
3. 参考 Prompt。
4. 图像生成。

重点是压缩并统一页内参数与结果栏，把中间画布设为真正的弹性区域，同时保持 Agent 独立常驻，不改变现有业务闭环。

### Phase D：资产与全局打磨

1. 资产的网格 / 列表双密度。
2. 全局中文术语和按钮文案。
3. 键盘、焦点、对比度、缩放与空态 QA。
4. 用受控 WebView2 按真实 DOM 流程逐页保留证据。

## 12. 视觉验收标准

- 首屏 3 秒内能回答：当前项目、当前素材、当前步骤、主要操作、后台状态。
- 任何页面只有一个实心紫色主按钮。
- 常规正文不小于 14 px，辅助文字不小于 12 px。
- Agent 始终默认可见，页面切换和任务运行不会自动折叠或替换它。
- Agent 左侧工作区在不同页面都能形成明确视觉重心；允许有意留白，不为了占满而增加内容。
- 复杂画布页的页内固定侧栏总宽不超过主工作区的 42%，中央画布保持弹性增长。
- 任务和导出页的留白围绕主体均衡分布，不再表现为内容贴在左上角后的偶然剩余。
- 3D 页面任何状态都不会只呈现空白灰黑视口。
- 同类标题、输入、按钮、空态和状态条跨页面保持同一尺寸和位置逻辑。
- 所有颜色状态均有文字或图标补充，不只依赖颜色。
- 125% / 150% Windows 缩放下无主操作裁切和不可达滚动区域。

## 13. 证据限制

本评审可以确认截图中的布局、层级、密度、文案和可见状态问题；不能仅凭截图确认：

- 实际颜色对比度数值。
- 完整键盘导航、焦点顺序和屏幕阅读器语义。
- 加载、失败、恢复和窗口缩放过程中的瞬时行为。
- 原生选择器、拖放、DPI 和多显示器表现。

进入实现阶段后，需要按 `docs/controlled-validation.md` 的 Hot-update desktop UI verification 流程，在已运行的受控 WebView2 主机上逐页验证真实 DOM 交互。
