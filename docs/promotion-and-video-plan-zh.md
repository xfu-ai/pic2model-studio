# AIPicToModel 推广与视频录制执行方案

> 适用版本：当前桌面工作台版本
> 方案目标：对外清晰介绍项目价值，完成一套可直接拍摄、剪辑和分发的推广内容
> 核心演示链路：用户描述目标 → Agent 理解当前项目 → 自动调用创作工具 → 用户审批/视觉确认 → Agent 继续执行 → 3D 结果与交付包

## 1. 推广结论

AIPicToModel 不应只被介绍为“图片转 3D 工具”，也不应被拍成需要用户逐页点击的传统软件。更准确的定位是：

**一个由 Agent 驱动、人在关键节点把关的本地 AI 资产生产工作台。**

用户不需要先理解所有页面和按钮，只需要告诉 Agent 想得到什么。Agent 会读取当前项目和资产，调用图片分析、Prompt、候选图、目标提取、三视图、3D 和模型处理工具，并在外部付费、候选选择、框选和质量确认等关键节点把控制权交还用户。

推荐主宣传语：

> 告诉 Agent 你想做什么，它会在当前项目里把图片、三视图和 3D 工作流推进下去。

推荐辅助宣传语：

- 它不是只回答问题的聊天框，而是能读取项目状态、调用工具并等待任务完成的工作流 Agent。
- 用户给出目标，Agent 负责拆解和执行；涉及费用、视觉判断和文件位置时，再由用户确认。
- 不再在聊天工具、图片工具、建模网站和本地文件夹之间来回搬运素材。
- 每一步生成物都进入项目资产，候选图、三视图和模型可以继续复用。
- 需要调用外部 AI 服务的操作先由用户确认，项目与密钥仍由本机管理。
- AI 负责加速流程，用户保留选图、框选、质量确认和最终导出的控制权。

### 1.1 推广叙事从“功能演示”改为“Agent 解决任务”

主宣传片不要按顺序讲六个页签，而要围绕一个用户目标展开：

```text
用户：把当前机器人概念图做成适合游戏原型的 3D，
      先检查是否适合建模，再准备三视图。
      我确认后按约 2 万面生成带纹理和 PBR 的模型，
      完成后打开预览。

Agent：
  读取当前项目和图片
    → 分析 3D 适用性
    → 生成三视图
    → 打开三视图确认页

用户：
  调整正/侧/背区域并确认质量
    → 批准外部 3D 任务

Agent：
  继续生成模型
    → 等待后台完成事件
    → 检查 GLB
    → 打开 3D 预览
```

视频需要清晰表现四种 AI 特性：

1. **理解上下文**：用户说“当前图片”“刚才的模型”时，Agent 能读取项目内真实资产和任务，而不是要求重新上传。
2. **多步执行**：一次目标可以触发分析、Prompt、生成、检查、转换等多个工具，而不只是回答一段建议。
3. **长任务续跑**：图片和 3D 任务进入后台；完成事件到达后，Agent 可以继续剩余步骤。
4. **人机边界明确**：Agent 自动做可追踪的工作，用户负责外部费用审批、候选选择、框选和视觉质量确认。

画面重点从“鼠标点了哪个按钮”改为：

- 用户输入的自然语言目标。
- Agent 正在调用的工具卡片。
- 项目资产和后台任务随执行产生变化。
- Agent 主动打开需要用户处理的工作区。
- 用户完成一次关键确认后，Agent 继续后续任务。
- 最终回答中展示生成图片或模型处理结果。

## 2. 推广目标

### 2.1 首轮目标

首轮推广不以大规模获客为第一目标，而是验证以下三件事：

1. 用户能否在 30 秒内理解“这是完整的 AI 3D 资产工作流，而不是单功能转换器”。
2. 游戏美术、独立开发者和 AI 创作者是否愿意申请试用、收藏项目或加入交流渠道。
3. 用户最关注的是出图质量、3D 质量、流程效率、可控性，还是本地项目管理。

### 2.2 建议衡量指标

| 层级 | 指标 | 首轮建议目标 |
| --- | --- | --- |
| 曝光 | 视频播放、封面点击率、完播率 | 先比较不同标题与开场的相对表现 |
| 兴趣 | 收藏、评论、私信、主页访问 | 重点记录真实工作流问题 |
| 转化 | 下载、试用申请、GitHub/产品页访问 | 每条内容只设置一个主要行动入口 |
| 质量 | 成功完成首次项目的比例 | 记录用户卡在哪一个页面 |
| 留存 | 7 天内再次打开项目或导出资产 | 判断产品是否进入真实生产流程 |

## 3. 目标用户与传播重点

| 用户 | 主要痛点 | 应重点展示 |
| --- | --- | --- |
| 独立游戏开发者 | 缺少完整美术团队，原型资产制作慢 | 从概念图快速得到可预览 GLB / 可导出 FBX |
| 概念设计师 | 参考图、Prompt、衍生图分散 | 内容/风格分析、双语 Prompt、候选版本管理 |
| 3D 美术与技术美术 | AI 结果不可控、来源难追踪 | 三视图人工确认、目标面数、GLB 检查与 FBX 转换 |
| AI 创作者 | 多个平台来回操作，文件容易混乱 | 单一桌面工作区、资产库、任务中心和 Agent |
| 小型工作室 | 长任务与外部费用难以管理 | 任务状态、失败恢复、外部调用前确认和本地凭据管理 |

首轮内容建议优先面向“独立游戏开发者 + AI 视觉创作者”。这两个群体最容易理解“一张图到 3D 原型”的直接价值。

## 4. 功能说明与对外表达

### 4.1 完整功能地图

| 功能模块 | 当前能力 | 对外价值表达 | 视频展示优先级 |
| --- | --- | --- | --- |
| AI Agent | 读取项目与资产、连续调用创作工具、接收后台完成事件、打开需确认的工作区 | 用户描述目标，Agent 负责拆解并推进多步工作流 | 最高 |
| 本地项目 | 新建、打开、最近项目、项目包导入导出 | 每次创作都有独立项目，不再靠临时文件夹拼流程 | 高 |
| 图片输入 | 系统文件导入、拖放、框选截屏 | 网页灵感、设计稿和本地图片都能快速进入工作流 | 高 |
| 图片主页 | 版本切换、缩放、平移、当前资产管理 | 始终围绕当前素材继续下一步 | 中 |
| 风格转化提示器 | 内容图与风格图独立分析、双语 Prompt、合并与编辑 | 把“画什么”和“怎么画”分开控制 | 高 |
| 图像生成 | 中英文 Prompt、智能扩写、候选数量、宽高比、候选选择与 PNG 导出 | 快速得到多个可比较版本，并选择一个继续生产 | 高 |
| 图片背景处理 | 本地纯色抠图、通道抠图、透明边裁切，以及外部复杂背景移除 | Agent 可根据背景类型选择本地或经批准的外部处理，不覆盖原图 | 最高 |
| 尺寸与格式标准化 | 指定宽高/最长边、保持比例、旋转、翻转、PNG/JPEG/WebP、质量与透明通道 | 用自然语言把零散素材整理成统一交付规格 | 高 |
| 本地图片放大 | 离线 2×/4× 放大，作为可追踪后台任务保存新资产 | 小图可先在本机增强，再进入精灵或 3D 流程 | 高 |
| 精灵图拆分 | 按行列网格拆分，或按透明连通区域识别不规则精灵；支持面积、边距和数量限制 | 一句话把 Sprite Sheet 变成一组独立受管精灵资产 | 最高 |
| 目标提取 | 直接框选、纯本地裁切、AI 独立目标图、AI 部件拆解 | 从复杂画面中获得更适合建模的干净目标 | 高 |
| 三视图 | 自动生成、正/侧/背区域调整、预览、质量确认、目标面数 | 在提交 3D 前加入人工质量关口 | 最高 |
| 3D 模型 | Tripo3D 任务、GLB 加载与交互预览、目标面数优化、截图 | 在桌面工作台中直接检查生成模型 | 最高 |
| 模型导出 | GLB 资产、FBX 转换与保存到文件夹 | 便于继续进入 Blender、Unity、Unreal 等后续流程 | 最高 |
| 资产库 | 图片、Prompt、三视图、模型等受管资产浏览和切换 | 生成物不是一次性结果，而是可继续使用的项目资产 | 中 |
| 任务中心 | 进度、筛选、失败原因、重试、取消/停止等待、结果跳转 | 长任务可以后台运行，失败后有明确恢复路径 | 中 |
| 安全与控制 | 系统凭据库存储密钥、外部生成前确认、脱敏诊断包 | 外部调用可见、可确认，敏感信息不在界面回显 | 中 |

### 4.2 推荐对外功能分组

官网、视频简介和宣讲材料不要列出所有按钮，建议收敛为五组：

1. **对 Agent 说出最终目标**：Agent 读取当前项目，拆解任务并选择受管工具。
2. **自动推进图片工作流**：分析内容与风格、准备 Prompt、生成候选、去背景、调整尺寸、拆分精灵图或提取建模目标。
3. **自动准备 3D 输入**：生成或修复三视图，并把用户带到需要视觉确认的工作区。
4. **人在关键节点把关**：外部费用、候选选择、目标选框、三视图质量和导出位置由用户决定。
5. **从生成继续到交付**：Agent 跟踪后台任务、检查 GLB、减面、转换 FBX 并整理受管交付包。

### 4.3 可安全使用的宣传表述

- “在一个本地桌面项目中串联图片、Prompt、三视图和 3D 资产。”
- “Agent 能读取当前项目、调用受管工具，并在后台任务完成后继续剩余步骤。”
- “用户描述目标，Agent 推进流程；涉及费用、审美和视觉质量时由用户确认。”
- “纯色去背景、尺寸标准化和精灵图拆分可以完全在本机完成，并保留原图与处理来源。”
- “复杂背景可以在用户批准后调用外部处理；Agent 不会静默把本地操作替换成外部调用。”
- “支持 Gemini 图像分析、Meshy 图像生成和 Tripo3D 建模等已配置外部服务。”
- “外部生成提交前需要用户确认，API Key 写入系统凭据库且不在界面回显。”
- “支持 GLB 预览，并可通过本地转换链路导出 FBX。”
- “长任务可在任务中心持续跟踪，生成结果作为项目资产保存。”

### 4.4 不建议使用的宣传表述

- 不说“完全离线生成 3D”。项目和部分处理在本机，但 AI 分析、图片生成和 3D 生成通常依赖外部服务。
- 不说“永久免费”。第三方服务可能产生用量或费用。
- 不说“任何图片一键变成生产级模型”。质量取决于输入、三视图、服务能力和后期要求。
- 不说“一句话后全程无人值守”。外部付费、候选选择、选框、三视图质量和项目外保存仍需用户操作。
- 不说“Agent 可以操作任意本地文件”。它只通过受管资产和桌面端授权能力工作。
- 不说“所有去背景都完全本地且效果相同”。纯色/通道抠图可本地完成，复杂场景可能需要外部服务。
- 不把尺寸调整说成“AI 超分”。普通标准化是本地重采样；只有明确选择本地放大时才使用离线放大模型。
- 不承诺固定生成时间。外部任务时长会随服务和网络变化。
- 不说“无需任何人工处理”。当前产品的优势正是保留选图、框选和质量确认。
- 不把受控演示数据描述成真实服务在几秒内生成的结果。

## 6. 首轮两周发布节奏

### 第 1–3 天：预热

- 发布 15 秒“原图 → 三视图 → 3D 旋转”无旁白循环。
- 发布一张完整流程图，征集用户最想看的环节。
- 用两个不同封面测试：“图片到 3D”与“本地 AI 资产工作台”哪个更容易被理解。

### 第 4 天：正式发布

- 发布 4–5 分钟 Agent 主宣传片。
- 同步发布 60 秒 Agent 精华版。
- 将 6–8 分钟逐页人工操作版作为教程或次日内容，不与主宣传片竞争定位。
- 产品页或 README 使用同一套演示素材，避免不同渠道出现不同产品定位。

### 第 5–9 天：功能拆解

- 第 5 天：一句话本地去背景、裁透明边并统一输出尺寸。
- 第 6 天：规则网格与不规则透明精灵图如何自动拆分。
- 第 7 天：Agent 如何从内容图 + 风格图生成 4 个候选。
- 第 8 天：Agent 为什么在三视图质量节点停下来等待用户。
- 第 9 天：一句话完成 GLB 检查、减面、FBX 转换和打包。

### 第 10–14 天：案例与反馈

- 发布一个适合流程的正向案例。
- 发布一个输入图不合适的失败案例，说明如何通过目标提取和三视图改善。
- 汇总高频问题，产出 FAQ。
- 根据评论决定下一轮主推“游戏资产”“电商产品 3D”或“角色原型”中的哪一条垂直方向。

## 7. Agent 应用场景库

以下场景都围绕当前 Agent 已具备的受管工具设计。每个场景都包含用户目标、Agent 的执行链、用户需要参与的节点和适合拍摄的 AI 特性。

### 场景一：一句话把概念图推进到游戏原型 3D

适用用户：独立游戏开发者、关卡原型设计师、游戏策划。

用户准备：

- 创建项目并导入一张主体完整的机器人、宝箱、家具或科幻道具图。
- 将该图片设为当前资产。

推荐用户指令：

> 检查当前图片是否适合制作游戏道具 3D。如果主体和结构足够清楚，先生成正、侧、背三视图并带我完成质量确认；我确认后，用多视图生成带纹理和 PBR 的模型，目标面数约 20000。完成后检查模型并打开预览。如果输入不适合，不要直接生成，先告诉我应该怎么处理。

Agent 执行链：

1. 检查当前项目、当前图片和可用能力。
2. 分析图片的 3D 适用性，包括主体完整度、遮挡和几何可读性。
3. 若适合，发起三视图生成；外部操作等待用户批准。
4. 三视图完成后，打开三视图工作区。
5. 等待用户调整正/侧/背区域并完成质量确认。
6. 按约 20000 面、纹理和 PBR 参数准备 3D 生成；再次等待用户批准。
7. 后台任务完成后检查 GLB，并打开 3D 预览。

用户参与：

- 批准三视图和 3D 外部任务。
- 调整三视图区域。
- 完成三视图质量确认。

主要卖点：

- 一条自然语言指令跨越分析、三视图、建模和预览。
- Agent 会先判断输入，不会不加检查地直接花费用生成。
- 长任务完成后继续剩余步骤。
- 用户只在视觉判断和费用节点介入。

视频金句：

> 我没有告诉它每个按钮怎么点，只告诉它最终要什么。

### 场景二：把两张参考图变成一组可选设计方案

适用用户：概念设计师、产品设计师、AI 绘图创作者。

用户准备：

- 导入一张内容参考图，例如机器人草图。
- 导入一张风格参考图，例如陶瓷、木雕或低多边形风格图。
- 为素材使用容易识别的名称。

推荐用户指令：

> 用“机器人草图”提供主体和结构，用“白色陶瓷参考”提供材质、色彩和光影。分别分析两张图，提取并合并中英双语 Prompt；把背景限制为纯色，要求主体完整、无遮挡、适合后续三视图，再生成 4 张 1:1 候选。不要替我选择最终方案。

Agent 执行链：

1. 在项目资产中找到两张指定参考图并检查详细信息。
2. 对内容图执行内容分析，对风格图执行风格分析。
3. 分别提取中英文 Prompt。
4. 合并内容和风格 Prompt。
5. 按“纯色背景、主体完整、适合三视图”的指令改写并验证 Prompt。
6. 准备 4 张 1:1 候选图，等待用户批准外部生成。
7. 任务完成后在对话中展示候选结果。

候选完成后的第二轮指令：

> 比较第 1 张和第 3 张，从轮廓完整、遮挡少、结构容易转成三视图三个方面说明差异，但不要替我切换当前资产。

用户选定后的第三轮指令：

> 使用第 3 张作为当前资产，继续准备三视图。

用户参与：

- 批准分析或图片生成等外部操作。
- 对候选结果做最终选择。

主要卖点：

- Agent 不只是生成图片，而是把内容、风格、生成约束和后续 3D 目标一起组织。
- Agent 可以比较候选并给出依据，但不会越权替用户做审美选择。
- 用户选定后，Agent 能基于同一个项目继续。

### 场景三：复杂角色或机械部件拆分

适用用户：角色设计师、硬表面建模师、需要拆件的游戏美术。

用户准备：

- 导入一张结构复杂但轮廓较完整的角色或机甲图。

推荐用户指令：

> 把当前机甲角色拆成适合独立建模的部件：头部、躯干、左右手臂、腿部和背部装备。先生成清晰的部件拆解图，然后打开目标提取，让我逐个确认要裁出的部件。不要替我确认选框。

Agent 执行链：

1. 检查当前图片。
2. 创建描述拆解部件和结构保持要求的受管 Prompt。
3. 发起语义部件拆解，等待用户批准外部操作。
4. 拆解图完成后打开目标提取工作区。
5. 等待用户绘制和确认矩形选区。
6. 使用已确认选区生成或裁出对应部件。
7. 将每个结果登记为项目资产，可继续处理下一个部件。

用户框选后的续接指令：

> 用刚才确认的选区提取头部，完成后保留拆解图，让我继续选择下一个部件。

用户参与：

- 批准 AI 拆解。
- 绘制、调整并确认矩形选区。
- 决定继续提取哪个部件。

主要卖点：

- Agent 可以规划复杂拆件流程并维护上下文。
- 视觉选区仍由人确认，避免 Agent 猜坐标后直接生成错误结果。
- 多个部件在同一个项目中保留来源关系。

### 场景四：Agent 自动去背景并整理透明素材

适用用户：电商设计、游戏 UI、图标制作、需要透明 PNG 的 3D 素材准备。

本地纯色背景推荐指令：

> 当前图片是纯色背景产品图。全程使用本地处理，不调用外部服务：从图片四角推断背景色，容差设为 20，只删除与画面边缘连通的背景，边缘羽化 2 像素并向内收缩 1 像素；然后裁掉多余透明边，保留 16 像素边距，输出 PNG 并设为当前资产。不要覆盖原图。

Agent 执行链：

1. 检查当前图片格式、尺寸和透明通道。
2. 调用本地 `remove_background_local`，使用颜色键、边缘连通限制、羽化和收边参数。
3. 调用 `trim_transparent` 裁掉多余透明区域并保留指定边距。
4. 检查生成资产的尺寸和透明通道。
5. 因结果唯一且用户已明确要求，将新 PNG 设为当前资产。

复杂背景推荐指令：

> 先判断当前背景是否适合本地纯色抠图。如果不是，不要强行用颜色键；告诉我原因，并在我确认后再使用外部去背景服务。

Agent 执行链：

1. 检查图片与背景特征。
2. 适合时走本地离线处理，无外部审批。
3. 不适合时停止本地颜色键处理并解释风险。
4. 用户明确确认后，才发起外部 `remove_background` 操作。

主要卖点：

- Agent 会区分本地确定性工具和外部 AI 工具，不会静默切换处理方式。
- 原图保留，去背景与裁边结果都是带来源关系的新资产。
- 本地路径不上传、无外部费用审批，适合高频素材清洗。

### 场景五：一句话拆分规则或不规则精灵图

适用用户：2D 游戏开发者、像素美术、动画与 UI 资源整理。

规则网格推荐指令：

> 当前图片是一张 4 列、2 行的精灵图。请完全在本地按网格拆成 8 张独立图片，最多输出 8 项，保留每格原始透明通道，不要调用外部服务，也不要替我选择某一张作为当前资产。完成后按从左到右、从上到下汇总每张尺寸。

Agent 执行链：

1. 检查当前图片尺寸。
2. 使用本地 `grid` 模式，参数为 4 列、2 行、最多 8 个输出。
3. 将余数像素完整分配到边缘网格，避免丢像素。
4. 创建 8 个受管子资产，并汇总尺寸。

不规则透明精灵推荐指令：

> 这张透明图里的精灵没有规则网格。请按独立非透明连通区域拆分，忽略面积小于 64 像素的噪点，每个精灵保留 4 像素透明边距，最多输出 32 项；全程本地处理。

Agent 执行链：

1. 读取透明通道。
2. 使用 `alpha_components` 模式识别独立连通区域。
3. 过滤小面积噪点。
4. 为每个组件保留透明边距，并遮掉其他组件。
5. 将结果作为当前精灵图的子资产写入项目。

主要卖点：

- 同时覆盖传统规则 Sprite Sheet 和自由排布透明图集。
- 不需要用户逐格手工裁切，也不需要外部 AI 服务。
- 每个精灵都保留来源，可继续统一尺寸、放大或导出。

### 场景六：根据素材条件自动放大并统一尺寸

适用用户：游戏 UI、跨平台资源交付、模型参考图和批量素材整理。

条件式处理推荐指令：

> 检查当前图片尺寸。如果最长边小于 512 像素，先使用本地离线放大 2 倍；然后保持宽高比，把最长边统一到 1024 像素，输出 WebP，质量 85，并保留透明通道。整个流程不要调用外部服务，也不要覆盖原图。

Agent 执行链：

1. 检查当前资产尺寸和透明通道。
2. 只有最长边小于 512 时，发起本地 `upscale_local` 2× 后台任务。
3. 后台完成事件到达后继续执行，而不是循环查询。
4. 调用 `normalize`，保持比例并限制最长边为 1024。
5. 输出 WebP、质量 85、保留透明通道。
6. 检查最终规格并汇总原图、放大结果和标准化结果。

多规格交付推荐指令：

> 以当前透明图为源，分别生成最长边 256 和 512 像素的 PNG 版本，都保持比例和透明通道。两个结果都保留在项目中，不要替我删除或覆盖原图。

可补充的标准化能力：

- 指定目标宽度或高度。
- 保持比例或按明确要求调整到指定尺寸。
- 顺时针旋转 0/90/180/270 度。
- 水平或垂直翻转。
- 输出 PNG、JPEG 或 WebP，并控制 JPEG/WebP 质量。
- PNG/WebP 保留透明通道；JPEG 会使用白色底色。

主要卖点：

- Agent 可以先读取尺寸再做条件判断，而不是固定执行同一套动作。
- 本地放大是可恢复后台任务，完成后 Agent 自动继续标准化。
- 一个自然语言规格可以形成多份可追踪交付资产。

### 场景七：只修复有问题的侧视图

适用用户：已生成三视图，但其中一个方向有错误的创作者。

推荐用户指令：

> 检查当前三视图。正面和背面保持不变，只重新生成侧视图；完成后打开三视图页面，让我重新确认区域和质量。

Agent 执行链：

1. 找到当前三视图集合并检查状态。
2. 只对 `side` 视图发起重新生成，等待用户批准。
3. 完成后更新同一三视图集合。
4. 打开三视图工作区，等待用户重新确认。

用户参与：

- 批准单视图重新生成。
- 重新检查侧视图及整体一致性。

主要卖点：

- 不必整套重做，Agent 能理解“只修侧面”并调用单视图修复能力。
- 保留已经满意的正面和背面，降低时间与费用浪费。

### 场景八：把现有 GLB 处理成可交付资产

适用用户：3D 美术、技术美术、Unity/Unreal 原型开发者。

用户准备：

- 当前项目已经有一个可解析的 GLB。

推荐用户指令：

> 检查当前 GLB 的网格、材质和贴图。如果模型可解析，把它优化到约 15000 面，再转换为 FBX；最后把原始 GLB、优化结果和 FBX 打成一个受管交付包。不要覆盖原模型。

Agent 执行链：

1. 检查 GLB 的真实性、网格、材质与本地处理能力。
2. 创建约 15000 面的优化模型，不覆盖原文件。
3. 将优化后的模型转换为 FBX。
4. 将原始 GLB、优化结果和 FBX 组成受管交付包。
5. 汇总每项结果及与原模型的关系。

如需保存到项目外：

> 打开模型页面，我要把 FBX 保存到自己选择的文件夹。

此时由桌面端让用户选择保存位置，Agent 不接触任意本地路径。

主要卖点：

- Agent 不只负责“生成”，还能完成模型检查、减面、格式转换和交付打包。
- 每个处理结果是新资产，原模型不会被覆盖。
- 适合表现本地 AI 工作流与传统工具链结合。

### 场景九：安全处理失败任务

适用用户：遇到网络错误、Provider 错误或不确定提交状态的用户。

推荐用户指令：

> 检查刚才失败的 3D 任务，说明失败发生在哪一步。如果系统明确标记为可以安全重试，就重试一次；如果远端提交状态不确定，或者可能重复收费，不要自动重试，告诉我应该先核对什么。

Agent 执行链：

1. 读取已知任务的真实持久化状态和脱敏错误。
2. 解释失败阶段与建议操作。
3. 只有用户已明确要求、且任务被系统标记为安全可重试时，才执行一次重试。
4. 对提交结果不确定或可能重复付费的任务停止自动重试。
5. 提醒用户核对第三方账户或任务记录。

用户参与：

- 明确授权安全重试。
- 对不确定提交在第三方账户中进行人工核对。

主要卖点：

- Agent 能处理异常，而不只是展示成功案例。
- 安全和费用判断来自持久化任务状态，不让模型猜测。
- “不会盲目重复付费”是可信 AI 产品的重要特性。

### 7.1 Agent 可以代替与不能代替的操作

| Agent 可以代替 | 仍由用户/桌面端完成 | 推广中的表达 |
| --- | --- | --- |
| 检查项目、资产、任务和能力 | 新建/切换项目 | “Agent 基于已打开的项目工作” |
| 分析图片内容、风格和 3D 适用性 | 从系统文件导入素材 | “素材进入项目后由 Agent 接手” |
| 提取、合并、改写和验证 Prompt | 配置 API Key | “凭据由系统凭据库管理” |
| 本地去背景、透明裁边、尺寸/格式标准化、2×/4× 放大 | 决定最终视觉效果是否合格 | “高频素材处理由 Agent 执行，原图始终保留” |
| 按网格或透明区域拆分精灵图 | 告诉 Agent 网格行列或拆分规则 | “一句话把图集变成受管精灵资产” |
| 生成候选、拆图和三视图 | 批准可能付费的外部调用 | “Agent 执行，费用由用户确认” |
| 基于用户明确选择切换当前资产 | 在多个候选中做最终审美选择 | “Agent 给建议，人做决定” |
| 发起 3D、检查模型、减面、转 FBX、打包 | 框选目标、确认三视图质量 | “视觉判断由用户把关” |
| 查询、取消或安全重试已知任务 | 选择项目外导出文件夹 | “Agent 不接触任意本地路径” |

推广时不要说“Agent 完全代替所有操作”。更准确、更可信的表达是：

> Agent 代替重复的工作流操作，人在费用、审美和视觉质量节点做决定。

## 8. 视频拍摄前准备

### 8.1 演示案例选择

建议选择一个具备以下特征的原创或已授权素材：

- 单个主体，轮廓完整，遮挡少。
- 正面或轻微透视，材质和配色明确。
- 不包含品牌 Logo、受保护角色或无法确认授权的内容。
- 最终模型在旋转时有明显的正面、侧面和背面信息。
- 适合游戏道具、机器人、家具或风格化角色，避免首支视频选择毛发、透明材质和复杂群像。

推荐首支案例：**风格化机器人、宝箱、座椅或单体科幻道具**。

本地图片处理专题另准备三份可验证素材：

- 一张纯色背景的 4×2 规则 Sprite Sheet，记录正确的 8 个单元格边界。
- 一张透明背景、精灵自由排布的不规则图集，包含 1–2 个可被面积阈值过滤的噪点。
- 一张最长边小于 512 像素的透明小图，用于证明“检查尺寸 → 离线放大 → 标准化”的条件执行。

这些素材都应准备人工确认的期望结果，避免只看“生成了几个文件”而忽略丢像素、网格错位、透明边缘和尺寸错误。

### 8.2 准备两个项目

为了避免外部任务等待破坏录制节奏，提前准备：

1. `Promo-Start`：只有原始图片和参考风格图，用于录制真实操作。
2. `Promo-Result`：已包含候选图、干净目标图、三视图、GLB 和 FBX，用于长任务完成后的无缝切换与补拍。
3. `Sprite-Local-Demo`：包含规则图集、不规则透明图集和小尺寸精灵，用于本地处理专题。

切换项目时在后期用“生成完成后”转场，不伪装成同一次实时等待。

### 8.3 服务与安全检查

- 提前确认 Gemini、Meshy、Tripo3D 和 Agent 所需凭据已经配置。
- 不录制 API Key 输入过程；设置页只可展示“已配置”状态或完全不进入。
- 真实调用前确认测试账户余额、并控制候选数量和目标面数。
- 正式录制不要启用受控/离线 Provider 后再把结果描述为真实 AI 输出。
- 如果使用受控演示数据，画面或说明中明确标注“演示数据/离线演示模式”。
- 不在桌面、文件选择器、标题栏、任务详情或诊断信息中暴露真实用户名、绝对路径、令牌和内部项目名。

### 8.4 画面设置

- 录制分辨率：优先 2560×1440，最终输出 1920×1080；短视频另裁 1080×1920。
- Windows 缩放：100% 或 125%，录制前确认文字不被截断。
- 帧率：操作演示 30 fps；大量 3D 旋转可使用 60 fps。
- 鼠标：打开点击高亮，但不要使用夸张的鼠标拖尾。
- 应用窗口：最大化；关闭通知、聊天软件、无关终端和浏览器标签。
- Agent 面板保持可见，这是产品定位的一部分。
- 使用同一套项目名、资产名和素材，避免镜头间名称跳变。
- 正式录制前清理测试项目名，例如 `Controlled WebView2 E2E`、`Untitled project`。

### 8.5 声音设置

- 推荐“后期配音 + 现场系统声关闭”，避免等待和误操作影响旁白。
- 人声响度建议约 -16 LUFS，峰值不超过 -1 dB。
- 背景音乐比人声低 16–22 dB，不使用强节拍盖住操作说明。
- 关键点击、结果出现和模型落地可加入轻微音效。

## 9. Agent 主宣传片脚本（建议 4 分 30 秒）

这支视频是首轮推广主片。主角不是六个功能页，而是右侧 Agent 如何接收目标、读取项目、连续调用工具、等待任务，并在必要时把工作交还用户确认。

### 9.1 主片故事

主场景使用“游戏道具概念图 → 三视图 → 3D → 优化与交付包”：

1. 用户已经打开项目并导入图片。
2. 用户给 Agent 一条完整目标。
3. Agent 检查图片并评估 3D 适用性。
4. Agent 生成三视图并打开确认页。
5. 用户只负责调整区域、确认质量和批准费用。
6. Agent 继续生成模型、检查结果并打开预览。
7. 用户追加“优化、转 FBX、打包”的交付要求。
8. Agent 完成本地模型处理并汇总结果。

主片中只保留两次必要的鼠标精细操作：

- 用户调整三视图区域。
- 用户旋转最终 3D 模型。

其余操作尽量从 Agent 输入区发起，强化“自然语言驱动工作流”。

### 9.2 分镜总表

| 时间 | 画面 | AI 特性 |
| --- | --- | --- |
| 00:00–00:15 | 输入一句目标，快切三视图和 3D 结果 | 自然语言驱动 |
| 00:15–00:40 | Agent 检查项目与当前图片 | 项目上下文 |

操作：

5. 鼠标掠过 `仅裁切选区（本地）`，说明本地裁切能力。
6. 点击 `生成独立目标图`。
7. 在“确认外部图像生成”中点击 `批准并提交`。

旁白：

> 框可以移动、缩放、撤销和重做。仅裁切可以完全在本地完成；如果要让 AI 清理背景和周围干扰，则在确认后生成独立目标图。

操作：

2. 点击 `设为当前资产`。
3. 点击 `进入三视图`。

旁白：

操作：

1. 确认“三视图来源”是刚才的目标图。

3. 点击 `自动拆分三视图`。
4. 在“确认外部图像生成”中点击 `批准并生成`。
5. 显示任务状态开始更新。
6. 用转场切到三视图拼图已加载的状态。

旁白：

2. 点击 `侧视图`，调整侧面框。
3. 点击 `背视图`，调整背面框。
4. 依次停留在右侧三个裁切预览上。

旁白：

> 三视图不是直接盲交给建模服务。每个区域都可以重新框选，右侧即时显示裁切预览，让用户先检查再提交。

录制注意：

- 拖框动作要慢，每次 1–2 秒。

6. 在“确认外部 Tripo3D 任务”中核对目标面数。
7. 点击 `批准并提交`。

旁白：

> 这里可以设置生成目标面数，并且必须完成人工质量确认。提交窗口会再次说明将发送哪些受管副本，以及本次目标面数。

旁白：

> GLB 可以直接在工作台中旋转、缩放和平移检查，也可以保存预览截图或交给系统浏览器继续查看。

#### 镜头 18：模型优化与 FBX（05:45–06:25）

3. 用任务完成转场显示优化后的受管模型。
4. 点击 `导出 FBX`。
5. 等待“FBX 转换完成，已保存在项目资产中”。
6. 点击 `保存到文件夹`。
7. 在系统文件夹选择器中选择演示导出目录。
8. 显示“FBX 已保存到所选文件夹”的成功状态。

旁白：

> 模型可以按目标面数创建优化任务。需要进入 Blender、Unity 或 Unreal 时，可将受管 GLB 转换为 FBX，再保存到选择的文件夹。

录制注意：

- 完整 FBX 转换依赖本机 Blender；基础三角网格可使用 Geometry FBX 兜底。正式拍摄前必须完整跑通一次。
- “导出 FBX”不要描述为直接支持所有材质和动画的无损转换。

#### 镜头 19：资产、任务与 Agent（06:25–06:50）

操作：

1. 点击左侧 `资产`，依次掠过原图、Prompt、目标图、三视图、GLB 和 FBX。

4. 点击发送。
5. 展示 Agent 基于当前项目给出的简短回答；如需要外部模型，使用预先录好的真实响应。

旁白：

> 原图、Prompt、候选、三视图、模型和导出文件都有来源关系；任务记录输入和输出。Agent 也不是脱离项目的聊天框，而是可以围绕当前资产继续协助。

#### 镜头 20：结尾行动引导（06:50–07:00）

旁白：

### 11.1 45 秒 Agent 本地图片处理专题

| 时间 | 操作与画面 | 旁白 |
| --- | --- | --- |
| 00:00–00:04 | 带纯色背景的精灵图瞬切为多张透明精灵 | “一张图集，怎样快速变成统一规格的透明游戏素材？” |
| 00:04–00:11 | 输入“本地去背景、裁透明边、按 4×2 拆分，最后统一最长边 256” | “我只把处理规则告诉 Agent。” |

| 00:25–00:33 | 4×2 网格先拆分为 8 张，资产页出现子资产 | “规则网格或不规则透明区域，都能拆成独立受管资产。” |
| 00:33–00:40 | 对独立帧裁透明边；小图按需放大并统一最长边 | “拆分后再逐帧裁边、放大和统一格式，网格坐标不会被提前破坏。” |

推荐输入：

> 当前图是 4 列 2 行的纯色背景精灵图。全程本地处理：先移除与边缘连通的背景并保持整张图集尺寸不变，再按 4 列 2 行拆成 8 张。拆分后分别裁掉每张的多余透明边并保留 4 像素边距，每张保持比例，最长边统一到 256 像素，输出 PNG。不要调用外部服务，不要覆盖原图。

录制与实际使用时注意：

- 规则网格必须先拆分，再对每一帧裁透明边；如果先裁整张图集，会改变网格原点和单元格尺寸。
- 不规则透明图集直接使用 `alpha_components`，该操作本身会按组件边界输出并保留指定边距。
- 8 张结果逐一标准化会产生多次本地工具调用；视频中可以加速工具卡，但不能伪装成一个不存在的批处理按钮。

## 13. 剪辑与包装规范

### 13.1 节奏

- 普通点击间隔 0.4–0.8 秒。
- 拖框和模型旋转保留完整动作，不用过快倍速。

- 一行不超过 18 个中文字，最多两行。
- 主字幕位于底部安全区；操作提示放在鼠标附近但不遮挡按钮。

- 不在画面上堆叠完整段落。

### 13.3 画面标注

建议统一四类标注：

- 黄铜色：用户主操作。
- 青绿色：AI 或后台任务状态。
- 白色：功能名称。
- 橙色：外部服务、费用和确认提醒。

### 13.4 转场

- 页面跳转使用 4–6 帧淡入淡出。
- 长任务前后使用“生成完成后 / 处理完成后”文字卡。
- 原图、目标图、三视图和模型之间尽量使用同一主体位置的匹配剪辑。

## 16. 首轮推广重点建议

首轮不要平均介绍所有功能。建议把传播资源集中在以下三点：

1. **Agent 真正执行工作流**：不是在聊天框里给操作建议，而是读取项目、调用工具、创建任务并在完成后继续。
2. **自动化与人工把关结合**：Agent 接管重复操作，外部费用、候选选择、框选和三视图质量由用户决定。
3. **本地素材处理能力**：去背景、透明裁边、尺寸统一、离线放大和精灵图拆分可在本机完成，不必为每一步调用外部服务。
4. **从生成延伸到交付**：除了候选图和 3D，还能检查模型、减面、转 FBX、打包，并保留完整资产关系。

如果首轮反馈更关注“Agent 是否真的能做事”，第二轮发布一条不剪工具执行过程的长镜头；如果更关注最终模型质量，做“Agent 先检查/修复输入与直接生成”的结果对比；如果更关注效率，做“人工跨平台操作 vs Agent 多步执行”的时间对比。
